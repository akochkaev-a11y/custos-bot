# Custos 0.1

Личный архив Telegram для @custos_dialog_bot. Python 3.12, SQLite, без сторонних Python-пакетов.

## Что реализовано

- Новые сообщения разрешённых личных чатов сохраняются в SQLite.
- При правке приходят исходный и новый текст, при удалении - сохранённая копия.
- Фото, видео, документы, аудио, голосовые, видеокружки, стикеры, анимация: сохранение идентификаторов и попытка локального скачивания.
- Ответ владельца любым текстом/смайликом на сообщение в разрешённом чате запрашивает копию вложения, которое Telegram передал боту.
- Доступ привязывается к одному Telegram user ID одноразовым кодом из установщика. Чужие подключения игнорируются.
- Входящие события и исходящая очередь сохраняются на диске. После перезапуска продолжается обработка.
- Бот не отправляет сообщения собеседникам, не удаляет их и не отмечает прочитанными.
- /status в личном чате с Custos показывает состояние.

## Границы версии

Одноразовые вложения экспериментальны: копирование работает только при наличии доступного файла в событии Telegram. Обход ограничений Telegram не реализован. Нельзя гарантировать повторение поведения Augramm без живой проверки. Тестировать с согласованными тестовыми фото и видео.

Предыдущая история до подключения не загружается. При удалении сообщения, которое бот не видел, придёт уведомление об отсутствии копии. При сетевом сбое более 24 часов Telegram может удалить недоставленные события.

Входящие обычные сообщения архивируются автоматически; уведомления приходят об изменениях, удалениях и при ответе владельца. Поддержка опросов, контактов, геопозиций, платных медиа и альбомов как единого блока не реализована. Уведомления при правке вложения содержат старое и новое вложение без подписей: контекст приходит отдельным текстом.

Локальные вложения: до 20 МиБ на файл, общий предел 2 ГиБ, резерв свободного диска 2 ГиБ, хранение 7 дней. При превышении лимитов новые файлы могут остаться только в виде Telegram file_id. Надёжность повторной отправки по file_id после удаления источника проверяется живым тестом. Тексты и версии хранятся без автоматического удаления. Нужен контроль роста SQLite через /status и df -h.

При аварии между успешной отправкой уведомления и записью результата в SQLite возможен повтор уведомления. Это доставка с возможными повторами, а не гарантия ровно одной отправки. Локальный архив не зашифрован; он защищён правами Linux. Тексты и токен не пишутся в журнал.

## Установка на Indira (Ubuntu 24.04)

Распаковать пакет в отдельную папку, перейти в неё, выполнить:

```bash
sudo bash install.sh
```

Установщик проверит тесты и токен, создаст отдельного системного пользователя custos, программу /opt/custos/custos.py, секрет /etc/custos/config.json и службу custos.service. Токен вводится скрыто и не попадает в историю команд. Существующие Atolin и GeoStrategy, их каталоги и порты установщик не меняет. Порты открывать не требуется: используется исходящий long polling HTTPS к api.telegram.org.

В конце установщик покажет `/start КОД`. Отправить эту команду в личный чат с @custos_dialog_bot. Код привяжет владельца. Прежний `/start` без кода не привязывает владельца.

В Telegram включить Secretary Mode в BotFather, Restrict bot usage - только владелец. В «Автоматизации чатов» добавить Custos, выбрать один тестовый чат, оставить чтение сообщений; другие действия не требуются.

```bash
systemctl status custos --no-pager
journalctl -u custos -n 40 --no-pager
```

Проверка после запуска: /status; тестовое новое сообщение; его редактирование; удаление для обоих; обычное фото с последующим удалением; ответ владельца на обычное и затем тестовое одноразовое вложение. Убедиться, что результат приходит в чат с Custos. Только после проверки расширить список доступных чатов.

Остановка: `sudo systemctl stop custos`. Отключение автозапуска: `sudo systemctl disable custos`. Данные остаются в /var/lib/custos. Повторный запуск install.sh обновляет программу, сохраняя конфигурацию и данные.

## GitHub

Рекомендуемый отдельный приватный репозиторий: akochkaev-a11y/custos-bot. Загрузить только содержимое этой папки. Токен, конфигурацию сервера и базу не загружать. GitHub Actions запускает тесты. Развёртывание на сервер выполняется отдельно и не настроено автоматически.

## Проверка разработки

```bash
python3 -m unittest discover -s tests -v
python3 -m py_compile custos.py
bash -n install.sh
```

Проверки моделируют события и ошибки Telegram локально. Живое подключение из среды подготовки недоступно, реальная отправка/скачивание и запуск systemd пока не проверены.
